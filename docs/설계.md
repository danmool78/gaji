# 가지 설계

정해 둔 결정을 한곳에 모았습니다. 구현하면서 바뀌면 이 문서를 먼저 고칩니다.

## 1. 원칙
1. **껍데기만 서비스한다.** 가지 사이트(Firebase)에는 코드와 동아리 명부만 있다. 실험 데이터는 없다.
2. **동아리 하나 = 가지 홈 폴더 하나.** 데이터 · 보고서 · 사진 · 백업 · 부원 명단이 모두 동아리 구글 드라이브 안에 있다.
3. **Firebase에 개인정보는 최소로.** 동아리당 마스터 한 명의 계정 ID만.
4. **한 화면에 한 가지 일, 보안은 보이지 않게.** 사람이 하는 일은 최소, 나머지는 자동.
5. **가지(계보)가 중심.** 실험을 열면 그 실험의 가지가 항상 보인다.
6. **지우지 않는다.** 실험은 '취소'로, 파일은 휴지통으로만.
7. **휴대폰과 태블릿 모두.** 태블릿 가로에서는 목록 + 상세 두 칸.

## 2. 전체 구조
```
[Firebase]  시스템 마스터 소유, 무료 플랜
 ├ Hosting : 가지 사이트 — 동아리 전용 주소 gaji.web.app/c/<주소이름>
 ├ Auth    : 동아리 마스터만 로그인 (구글)
 └ Firestore 동아리 명부 : 동아리당 문서 1개 (아래 3장)

[동아리 구글 드라이브]  학교 공유 드라이브 권장 — 동아리 마스터 소유
 ├ 가지 데이터 (시트)
 ├ 동아리 연결기 (Apps Script 웹 앱, 마스터 권한으로 실행) ← 부원 요청을 받아 시트·폴더에 읽고 씀
 ├ 실험/<코드 제목>/ 보고서 문서 · 사진
 ├ 보관/ · 백업/ · 로고/
```
- 부원은 구글 로그인 없이 **연결기**를 통해 사용한다. 연결기는 동아리 드라이브 안에서 돌아가므로 서버 비용 0원.
- 관리자(2~3명)는 구글 로그인으로 드라이브에 직접 접근할 수 있다(전체 내보내기 · 백업 · 복구).

## 3. Firebase 동아리 명부 (`clubs/<주소이름>`)
| 항목 | 개인정보 | 읽을 수 있는 사람 |
|---|---|---|
| 주소 이름, 동아리 이름, 로고, 색 | 아님 | 누구나 (로그인 화면 표시용) |
| 연결기 주소, 데이터 시트 ID | 아님 | 동아리 마스터 · 시스템 마스터 (부원 기기는 연결기 주소만 받음) |
| **동아리 마스터 계정 ID 1개** | 최소 | 동아리 마스터 · 시스템 마스터 |
| 사용 현황 숫자: 부원 수, 실험 수, 마지막 사용일, 버전 | 아님 | 동아리 마스터 · 시스템 마스터 |
| 마스터 인계 코드(해시), 만료 시각 | 아님 | 쓰기만 |

**저장하지 않는 것:** 부원 · 관리자 이름과 이메일, 학번, 실험 내용.

## 4. 사람과 역할
| 역할 | 로그인 | 어디서 관리 | 할 수 있는 일 |
|---|---|---|---|
| 시스템 마스터 (제작자, 넘기지 않음) | Firebase (구글) | Firebase `system/config` | 기능 업데이트, **동아리별 사용 현황 숫자 보기**, 마스터 분실 시 복구. 실험 내용은 볼 수 없음. 본인 예비 계정만 추가 가능 |
| 동아리 마스터 (1명) | Firebase (구글) | Firebase 명부 | 동아리 만들기, 연결기 설치, 관리자 지정, 마스터 넘기기 |
| 관리자 (2~3명) | 구글 | 드라이브 설정 시트 (마스터만 편집) | 부원 명단, 기기 승인, 비공개 실험, 백업 · 복구, 지원 요청 |
| 부원 | **학번 + 개인 코드** | 드라이브 부원 시트 | 기록 작성 · 수정 |

### 마스터 넘기기 (동아리끼리)
- 가지 시스템은 제작자가 계속 운영한다. 넘기는 것은 각 동아리의 마스터뿐이다.
- 현재 마스터가 '마스터 넘기기' → **일회용 인계 링크**(24시간) → 새 마스터가 링크로 들어와 구글 로그인 → 명부의 마스터 ID 교체. 예전 마스터 정보는 남지 않음.
- 마스터 연락 두절: 담당 선생님 요청 → 시스템 마스터가 확인 후 교체.

## 5. 부원 사용 흐름 (복잡하지 않게)
1. 관리자가 부원 시트에 **학번 · 이름** 추가 → **개인 코드 4자리 자동 생성** → 부원에게 알려 줌.
   - 코드는 해시(로그인 확인용)와, 연결기 비밀 열쇠(스크립트 속성)로 잠근 값으로 저장. 부원은 승인된 기기에서 **설정 → 내 개인 코드 보기**로 언제든 다시 볼 수 있음. 시트를 열어도 코드는 보이지 않음.
2. 부원이 동아리 주소를 열고 **학번 + 개인 코드** 입력 → "승인 기다리는 중".
3. **"기장님께 승인 요청 보내기"** → 휴대폰 공유창(카톡 등)에 메시지 자동 작성:
   `기장님, 가지 새 기기 승인 부탁해요 / 김OO (20315) · iPad · 확인 숫자 4821 / [승인 링크]`
4. 관리자가 링크 → 요청 확인(이름 · 기기 종류 · 확인 숫자 · 이미 쓰는 기기 수) → **승인**.
5. 부원 화면이 자동으로 열림. 이후 그 기기는 **열면 바로 사용**.

### 동아리 마스터의 기기
- 드라이브 연결 때 가지가 **마스터 키**(40자)를 만들어 연결기에는 해시만, Firebase `clubs/<주소>/secret/key` 에는 키를 저장(동아리 마스터만 읽음, 시스템 마스터도 못 읽음).
- 구글로 로그인한 마스터는 새 기기에서 학번만 넣으면 승인 없이 연결. 마스터를 넘겨받은 사람도 같은 방법으로 연결 → 시트의 마스터 역할이 새 사람에게 옮겨지고 예전 마스터는 관리자로.
- 키를 잃으면 시트 '설정' 탭의 `masterKeyHash` 값을 지우고 다시 연결(시트 편집 권한 = 드라이브 주인만 가능).

## 6. 보안 (자동, 설정 화면 없음)
| 장치 | 내용 |
|---|---|
| 기기 승인 | 코드를 알아도 새 기기는 관리자 승인 없이는 못 들어옴 (외부 유출 · 코드 공유 차단) |
| 기기 수 | **제한 없음.** 한 사람이 6대 이상이면 관리자 화면에 '기기 많음' 표시만 |
| 자동 정리 | 60일 안 쓴 기기 · 학기 바뀔 때 승인 만료 |
| 본인 알림 | 내 이름으로 새 기기가 승인되면 다음 접속 때 알림 → '내가 아님'으로 즉시 차단 |
| 잠금 | 코드 5번 틀리면 그 기기 30분 잠금 |
| 명단에서 빼기 | 그 사람의 모든 기기 즉시 차단 |
| 긴급 차단 | 관리자 '모든 기기 로그아웃' |
| 내보내기 제한 | 부원 화면은 필요한 만큼만 불러옴. 전체 내보내기 · 백업은 구글 로그인 관리자만 |
| 접속 기록 | 기기 · 시각 · 부원. 이상한 대량 조회는 차단하고 관리자 알림 |
| 공용 태블릿 | 승인 때 '공용' 체크 → 쓸 때마다 개인 코드, 닫으면 자동으로 나감, 누구 기기로도 세지 않음 |
| 비공개 실험 | 실험 상세의 자물쇠 → 담당자와 관리자만 보임 (대회 준비 등) |
| 중요한 일 | 결과 판정 · 삭제 · 단계 되돌리기 · 설정은 관리자만 |

- 막을 수 없는 것: 승인된 자기 기기를 빌려주기, 화면 캡처 → 기록에 본인 이름으로 남고, 가입 때 '내 코드와 기기를 빌려주지 않는다' 약속.
- 고급 설정(숨김): 부원도 학교 구글 계정으로 로그인하는 모드.

## 7. 드라이브 구조
```
가지 홈 폴더 (예: 공유 드라이브 "가지 - ○○동아리")
 ├ 📊 가지 데이터           (시트)
 ├ ⚙ 동아리 연결기         (Apps Script)
 ├ 📁 실험/<실험코드 제목>/  보고서 문서, 사진 (<코드>_01.jpg …)
 ├ 📁 보관/                 가지 보관 2026 … (연도별 시트)
 ├ 📁 백업/                 데이터 시트 주간 사본
 └ 📁 로고/
```
- 공유 드라이브 권장: 파일이 개인이 아니라 동아리 소유 → 졸업생 계정 삭제에도 안전, 인계는 멤버 변경으로 끝.
- 연결기가 마스터 권한으로 파일을 만들므로 부원이 만든 보고서 · 사진도 동아리 소유가 된다.

## 8. 데이터 시트 탭
| 탭 | 내용 |
|---|---|
| 실험 | 실험 · 아이디어 · 질문 · 자료 한 줄씩 |
| 연결 | 출발 · 도착 · 관계(이어서/파생/질문/자료/관련) |
| 측정 | 실험 · 조건 · 회차 · 값 · 제외 · 메모 |
| 번호 | 한 줄 추가 = 새 고유번호 (연결기가 잠금으로 겹치지 않게) |
| 파일 | 파일 장부: 파일 ID · 종류 · 실험 번호 · 이름 · 만든 사람 · 날짜 |
| 부원 | 학번 · 이름 · 개인 코드(해시) · 상태 |
| 기기 | 기기 ID · 부원 · 종류 · 승인자 · 승인일 · 마지막 사용 · 공용 여부 |
| 설정 | 동아리 이름 · 관리자 구글 계정 · 시트 버전 (마스터만 편집, 범위 보호) |
| 기록 | 누가(부원/기기) 무엇을 바꿨는지, 접속 기록 |

- 고유번호: `EXP-20`(불변) / 실험 코드 `26-BIO-020`.
- 긴 글(보고서)과 사진은 시트에 넣지 않는다 → 10년 써도 한도의 약 4%.

## 9. 속도와 한도
- 처음 열 때 한 번에 읽고, 이후에는 '마지막 수정 시각'만 확인해 바뀐 것만 다시 읽는다.
- 학년도 마감 때 지난 기록은 보관 시트로. 계보가 필요할 때만 보관 시트를 읽는다.
- 연결기(Apps Script) 무료 한도와 Firebase 무료 한도 안에서 동작. 명부는 동아리당 문서 1개.

## 10. 지우기 실수 대비 · 백업
| 겹 | 방법 |
|---|---|
| 막기 | 부원은 드라이브 직접 접근 없음(연결기만), 설정 탭 범위 보호, 삭제 대신 취소 |
| 되살리기 | 드라이브 휴지통 30일, 시트 버전 기록 |
| 백업 ① | 관리자가 가지를 열 때 주 1회 '백업' 폴더에 데이터 시트 사본 |
| 백업 ② | 같은 때 관리자 **개인 드라이브**에도 사본 |
| 백업 ③ | 연결기 예약 실행이 매주 관리자들에게 데이터 엑셀(.xlsx) + 변경 요약 메일 |
| 복구 | '백업에서 복구' → 새 데이터 시트, 번호 이어짐 |
| 알림 | 시트 · 홈 폴더가 안 보이면 복구 안내, '파일 점검'으로 사라진 파일 목록 |

## 11. 시스템 마스터의 사용 현황 화면
- 동아리 목록: 동아리 이름 · 만든 날 · 부원 수 · 실험 수 · 마지막 사용일 · 가지 버전 · 오래 안 씀 표시.
- 숫자는 연결기가 하루 한 번 명부에 보냄. 이름 · 이메일 · 실험 내용은 없음.

## 12. 지원 요청 (제작자도 기록을 못 보므로)
- 관리자 '제작자에게 지원 요청' → 기간(3 · 7 · 14일) → 데이터 시트 **읽기 전용** 공유, 자동 만료, '지원 종료'로 즉시 해제, 기록 탭에 남김.
- 학교가 외부 공유를 막으면 '지원용 사본 내보내기'(엑셀, 이름 가리기 선택).
- '오류 보고': 실험 내용 없이 오류 메시지 · 화면 · 버전만.

## 13. 업데이트
- 화면(사이트)은 시스템 마스터가 한 번 배포하면 모든 동아리에 적용.
- **연결기 = 껍데기 + 본체.** 동아리 시트에는 짧은 껍데기(`public/connector.gs`)만 한 번 넣는다. 껍데기는 10분마다 가지 사이트의 본체(`/core.js`)를 받아 실행하고, 스크립트 속성에 마지막 판을 보관 → 사이트 장애 때도 동작.
- 본체가 바뀌면 모든 동아리에 자동 적용. 다시 배포할 필요 없음 (권한 범위가 늘어나는 변경만 예외).
- **투명성:** 본체는 누구나 볼 수 있는 주소에 공개. 동아리가 원하면 시트 '설정' 탭 `autoUpdate = off`로 멈춤(마지막 판 유지). 본체가 아닌 내용은 받지 않음.
- 시트 구조는 새 본체가 필요한 열을 자동으로 추가 (지우지 않음).
- 원본 시트: 껍데기가 들어 있는 '가지 데이터 (원본)'을 링크 공유 → 마스터는 사본 만들기 한 번으로 코드 붙여넣기 없이 시작.

## 14. 실험 과정 (한 실험이 보고서가 되기까지)
| 단계 | 화면 | 남는 것 |
|---|---|---|
| 계획 작성 | 계획서: 목적 · 가설 · 변인(조작 · 종속 · 통제) · 준비물 · 방법 · 안전 · 역할 · 예상 · 참고 | `plan` |
| 검토 중 | 다른 부원 2명 승인(본인 승인 불가) · 칸마다 첨삭 · 수정 요청 → 고쳤어요. 관리자는 검토 없이 진행 가능 | 댓글 탭 |
| 준비 중 | 준비물 + 기본 항목 체크리스트 → 출발 신호 자동 | `prep` |
| 실험 당일 | 진행 도우미: 방법을 한 단계씩 체크(시각), 관찰 · 바꾼 점 · 문제 메모, 측정값 바로 넣기 | `run` |
| 실험 완료 | 결과 기록: 측정 방식 5가지(조건별 반복 · 시간 변화 · 두 값 관계 · 자유 표 · 관찰), 그래프, 관찰 · 고찰 · 결론 · 다음 | `report` |
| 기록 완료 | 보고서 11칸 자동 구성 · 인쇄/PDF · 칸마다 첨삭 · 관리자 판정 · 확정(잠금) | `report.final` |

- 지운 항목은 휴지통(만든 사람 · 관리자가 되살림). 실험은 '취소'로 기록을 남길 수 있음.
- 가지 옮기기: 이어진 부모를 바꾸거나 뿌리로 떼기(이어진 실험도 함께). 연구 줄기는 고르거나 새로 짓기.
- 찾기: 제목 · 번호 · 계획서 · 진행 메모 · 결과 · 고찰 · 댓글 내용, 연도 · 분야 · 사람 · 단계로 거르기.
- 저장은 화면에 먼저 반영하고 뒤에서 연결기로 보냄(약 5초). 저장 중 창을 닫으면 붙잡음.
- 열 때는 이 기기에 보관한 마지막 데이터로 바로 보여 주고 뒤에서 최신으로 맞춤(기기에서 나가면 지움).
